# Deploying the public demo (free tiers)

This guide puts MaintainIQ online with:

| Part | Service | Cost |
|---|---|---|
| Database | TiDB Cloud **Starter** (MySQL-compatible), AWS Frankfurt | Free; no payment method needed |
| App (API + frontend) | Render **free** web service, Frankfurt | Free; sleeps after 15 min idle |
| Nightly demo reset | GitHub Actions | Free |

Console screens change from time to time, so button names below may differ slightly. **Never add a payment method or raise a spending limit**: the free tiers are enough for this demo.

> **Keep secrets out of chats, issues, commits and screenshots.** Database passwords go only into the TiDB console, the Render dashboard, GitHub *secrets*, and the git-ignored file in Part B. The demo password is the one value that is deliberately public.

Choose the public demo password now. The README uses `MaintainIQ-Demo-2026`; if you choose another, update the README too. The same value is used in Parts B, C and D.

---

## Part A: Create the free TiDB database

1. Go to **tidbcloud.com** and sign up (GitHub, Google or email). Skip any offer to add billing details.
2. Create a cluster:
   - Plan: **Starter** (the free one).
   - Cloud provider: **AWS**. Region: **Frankfurt (eu-central-1)** if it is listed; otherwise the nearest European region (then pick the closest Render region in Part C).
   - Name: `maintainiq-demo`.
   - Spending limit: leave it at **0 / free**.
3. Open the cluster and click **Connect**:
   - Connection type: **Public**.
   - Click **Generate password** and store it in a password manager. This is the **admin** password.
   - Note the **host**, the **port** (`4000`) and the **user**. The user looks like `xxxxxxxx.root`; the `xxxxxxxx.` prefix is your cluster's prefix.
   - TLS is required. The app already uses it when `DB_SSL=true`.
4. Open the cluster's **SQL Editor** and run the following, replacing `PREFIX` with your prefix and choosing a new strong password:

   ```sql
   CREATE DATABASE maintainiq;
   CREATE USER 'PREFIX.miq_app' IDENTIFIED BY 'a-new-strong-password';
   GRANT SELECT, INSERT, UPDATE, DELETE ON maintainiq.* TO 'PREFIX.miq_app';
   ```

   The two users have separate jobs:
   - `PREFIX.miq_app` is the **app user**. It can only read and write data, and it is what Render uses.
   - `PREFIX.root` is the **admin user**. It is used only to create the tables: in Part B and by the nightly reset.

## Part B: Load the demo data (once)

1. In the project folder, create a file named **`.env.deploy`**. It is git-ignored by the `.env.*` rule, so it can never be committed. Put the **admin** details in it:

   ```
   NODE_ENV=production
   ALLOW_DB_RESET=true
   DB_SSL=true
   DB_HOST=<TiDB host>
   DB_PORT=4000
   DB_USER=PREFIX.root
   DB_PASSWORD=<admin password>
   DB_NAME=maintainiq
   SEED_PASSWORD=MaintainIQ-Demo-2026
   ```

2. Run:

   ```bash
   node --env-file=.env.deploy scripts/db-setup.js
   ```

   It prints the table counts: 6 users, 12 machines, 16 work orders, 97 downtime events, 2160 energy readings.
3. Delete `.env.deploy` when you no longer need it.

## Part C: Put the app on Render

1. Go to **render.com** and sign up **with GitHub**. A card isn't needed for free services.
2. Click **New → Blueprint**. When GitHub asks which repositories Render may access, choose **Only select repositories → Jackhaider/maintainiq**.
3. Pick the `maintainiq` repository and the `main` branch. Render reads [`render.yaml`](../render.yaml) and shows one web service, `maintainiq`, with plan **Free** and region **Frankfurt**. Check that it says **Free** before continuing.
4. Fill in the values Render asks for. Use the **app user** here, not root:

   | Key | Value |
   |---|---|
   | `DB_HOST` | TiDB host |
   | `DB_PORT` | `4000` |
   | `DB_USER` | `PREFIX.miq_app` |
   | `DB_PASSWORD` | app user's password |
   | `DB_NAME` | `maintainiq` |
   | `DEMO_PASSWORD` | `MaintainIQ-Demo-2026` (or your chosen demo password) |

   Render fills in the rest itself:
   - `JWT_SECRET` is generated by Render and never shown to anyone.
   - `NODE_ENV`, `DB_SSL`, `DEMO_MODE` and `JWT_EXPIRES_IN` come from `render.yaml`.
5. Click **Apply** and wait for the deploy to finish. The public URL looks like `https://maintainiq-xxxx.onrender.com`.
6. Open `https://<your-url>/api/health`. It should show `{"status":"ok","database":"ok", ...}`.

## Part D: Turn on the nightly reset

In GitHub, open **Jackhaider/maintainiq → Settings → Secrets and variables → Actions**.

1. Add these under **Secrets**, using the **admin** user, because the reset recreates the tables:

   | Secret | Value |
   |---|---|
   | `DEMO_DB_HOST` | TiDB host |
   | `DEMO_DB_PORT` | `4000` |
   | `DEMO_DB_USER` | `PREFIX.root` |
   | `DEMO_DB_PASSWORD` | admin password |
   | `DEMO_DB_NAME` | `maintainiq` |

2. Add these under **Variables**:

   | Variable | Value |
   |---|---|
   | `DEMO_PASSWORD` | `MaintainIQ-Demo-2026` (same as on Render) |
   | `DEMO_RESET_ENABLED` | `true` |

3. Go to **Actions → Demo reset → Run workflow** to test it once. It should finish green, and `/api/health` should still be ok.

The reset then runs every day at 02:30 UTC. Notes:
- GitHub pauses scheduled workflows in a repository with no activity for 60 days. Re-enable it from the Actions tab if that happens.
- During the few seconds of a reset, requests may fail. Visitors just reload.

## Part E: Check the live demo before sharing it

Go through this list, then add the URL to the README, the repository description and your CV:
- `/api/health` is ok.
- The login page shows the demo box, and both buttons sign in.
- Supervisor: the dashboard, reports and user management load.
- Operator: sees only Press Shop machines and gets "no permission" for reports.
- Create a work order, assign it, add a note and close it. Then delete it.
- Try to delete a seeded work order, or to deactivate the demo operator. Both are refused with a "demo" message.
- Ten wrong passwords in a row lead to "Too many failed sign-in attempts".
- The browser shows the HTTPS padlock, and there are no errors in the developer console.

Expect a pause of up to about a minute on the first visit after the service has been idle. Mentioning it next to the link helps.
